# TSFM Reality Check: the website

Static single-page app (Vite + React + TypeScript). Lessons run Python in the browser
(Pyodide, in a Web Worker); results are read from `public/data/results` (exported by
`make publish-results`); progress is stored in IndexedDB and synced to Supabase.
Design decisions: `docs/DECISIONS.md` D-043 to D-051 and D-055 to D-058 (the guided
journey). Deployment: `docs/DEPLOY.md`.

## The guided journey

A first-time visitor always knows what to do next, and why:

- **The tour.** The first visit to Home opens a three-screen tour, ending with
  "Start lesson 00". It can be re-opened from *Tour* in the menu.
- **Do this next.** Home shows one card with the next step of the whole project: what, why,
  how long, and one button.
- **Your path.** This page shows the route: eight phases, from the tour to a published,
  audited study.
- **Your laptop.** Steps done there (set up, run the study, publish, test) have their own
  pages. Each gives numbered commands for macOS, Windows (WSL) or Linux, says what you should
  see, and checks the output you paste back.
- **Where you are.** Every lesson and task page shows a breadcrumb (for example
  "Phase 3 · Foundations · step 2 of 4") and ends with a single "Next step" button.

How it works:

- *Where the route is defined.* `content/journey.yaml` (phases and order) and
  `content/tasks/*.yaml` (the terminal steps), validated at build time by
  `scripts/journey.mjs`.
- *What decides the next step.* `src/lib/journey.ts` computes it from your progress; it is
  a pure function, tested in `tests/journey.test.ts`.
- *How pasted output is checked.* `src/lib/cliparse.ts` reads it, using markers taken from
  the CLI's code. It is tested on real captured output in `tests/fixtures/cli/`.
- *Where the state is stored.* Journey state is in the table `journey_state`, local first
  and synced like all progress.
- *What completes itself.* Once a real run of the study (`default`, non-synthetic) is
  published, the site marks phases 1, 2 and 5 done by itself.

```bash
npm ci
npm run dev        # http://localhost:5173 (runs scripts/prebuild.mjs first)
npm run lint       # ESLint + TypeScript
npm test           # unit tests (Vitest), incl. RLS on a real Postgres (PGlite)
npm run e2e        # production build + Playwright (Chromium) under the production headers
```

| Path | What |
|---|---|
| `content/` | **The lessons**, the journey and the terminal tasks (single source; format in `content/README.md`) |
| `scripts/prebuild.mjs` | Compiles content and the journey, checks Pyodide packages/imports, builds the `tsfm_rc` wheel, research status |
| `src/lib/` | Local store, sync, SM-2, progress, journey and output checks, Supabase client, error explanations |
| `src/py/` | Python worker (Pyodide) and the page-side runner |
| `src/pages/` | Home, Tour, Your path, terminal tasks, Lessons, Lesson, Results, Review, Notes & log, Research status, Progress & sync |
| `supabase/migrations/` | Postgres schema with row-level security and the last-write-wins trigger |
| `public/data/results/` | Published results (committed; generated by `make publish-results`) |
| `tests/`, `e2e/` | Unit and browser tests; `tests/fixtures/cli/` real terminal output for the output checks |

Lesson code that needs Python packages is tested in a real browser only where
`cdn.jsdelivr.net` is reachable; CI sets `REQUIRE_PYODIDE=1` so it can never be skipped there.
